# Player box redesign, anime catalog, and recommendations rails

This change replaces the standalone Player route with an inline PlayerBox component on detail pages, adds a full Anime section (navigation, page, and server endpoints), introduces "More Like This" / "Related Series" recommendations on detail pages, and extends the home page with "Ongoing Series" and "Trending Anime" rails. The anime endpoints use TMDB's discover API filtered to genre 16 (Animation) + Japanese-language originals rather than a dedicated anime API. The Player route now just redirects to the detail page with `?autoplay=true`.

**Watch for:** The anime filtering strategy (genre=16 + `with_original_language=ja`) will surface non-anime Japanese animated shows and miss anime produced outside Japan (confirmed). Hero randomization from the prior review is still unfixed — each settling query re-renders Home and picks a new hero (confirmed). The "Ongoing" anime endpoint uses a 30-day `air_date.gte` heuristic that doesn't distinguish finished shows from actually ongoing ones (confirmed).

## High-level view

The PlayerBox component is a 16:9 backdrop thumbnail with a centered play icon that swaps to a VideoPlayer iframe on click. When `item.backdrop_url` is missing, the idle state renders a blank dark box with a floating play button — functional but potentially confusing for items without TMDB backdrop art.

The anime catalog reuses TMDB discover with `with_genres: '16'` and `with_original_language: 'ja'`. This avoids a third-party anime API but the filter is narrow: it excludes anime produced outside Japan and includes non-anime Japanese animation (children's cartoons). The "Ongoing" endpoint uses a 30-day `air_date.gte` window rather than TMDB's `with_status=Returning Series`, so recently-finished shows still appear.

The home page now fires 4 parallel queries on mount. Combined with the unfixed hero randomization bug (Math.random in render body without useMemo), each re-render triggered by a query settling reshuffles the featured hero.

The server's recommendation routes execute the pathname regex twice per request (once in the condition, once to extract captures). Minor performance waste but inconsistent with the existing season route which stores the match.

<details>
<summary>Issues (4)</summary>

1. **Anime filter excludes non-Japanese anime** — `with_original_language: 'ja'` will miss anime co-produced with Korean or Chinese studios. Consider dropping the language filter or adding keyword-based filtering for broader coverage. (confirmed)
2. **Hero randomization still unstable** — `Math.random()` runs in the render body without `useMemo` on both web and mobile Home. Each settling query triggers a re-render that picks a new hero. Wrap in `useMemo` keyed on `movieItems`. (confirmed)
3. **"Ongoing" anime heuristic is imprecise** — The 30-day `air_date.gte` window captures shows that aired recently but doesn't guarantee they're ongoing. A show that aired its finale 20 days ago still appears. Use TMDB's `with_status` parameter ("Returning Series") for semantic correctness. (confirmed)
4. **Double regex execution on recommendation routes** — Each recommendation route calls `pathname.match(...)` twice. Store the match result in the condition to avoid redundant regex execution. (confirmed)

## PlayerBox fallback state

When `item.backdrop_url` is falsy, the idle state renders:

```jsx
<div className="w-full h-full bg-background-elevated" />
```

This produces a blank dark rectangle with only the play circle overlay — no title, no placeholder icon. For movies or shows without TMDB backdrop art, the user sees a featureless box. Consider rendering the poster image as fallback, or at minimum showing the title text within the box.

## Anime via TMDB discover filtering

The server implements three anime endpoints:

```
/api/anime/trending  → discover/tv, genre=16, lang=ja, sort=popularity.desc
/api/anime/ongoing   → discover/tv, genre=16, lang=ja, air_date.gte=30d ago, sort=popularity.desc
/api/anime/top-rated → discover/tv, genre=16, lang=ja, sort=vote_average.desc, vote_count.gte=100
```

The `with_original_language: 'ja'` filter means shows like *Tower of God* (Korean webtoon adaptation animated in Japan but potentially catalogued differently) may or may not appear depending on TMDB's metadata. More critically, anime produced or localized outside Japan won't show up at all.

TMDB's `with_status` parameter supports "Returning Series" which would be semantically correct for the "Ongoing" endpoint. The current 30-day heuristic will include shows that just ended their run and exclude long-running shows that haven't aired in 31+ days (e.g., seasonal breaks).

## Hero instability with additional queries

Both web and mobile Home now issue 4 queries on mount:

```jsx
const heroItem = movieItems.length > 0
  ? movieItems[Math.floor(Math.random() * Math.min(movieItems.length, 5))]
  : null;
```

Adding 2 more queries (on-the-air, anime trending) means 2 more potential re-renders as they settle, increasing the probability of visible hero flickering. The fix remains: `useMemo` keyed on `movieItems`.

## Recommendations route double-match

```js
else if (pathname.match(/^\/api\/movies\/(\d+)\/recommendations$/)) {
  const match = pathname.match(/^\/api\/movies\/(\d+)\/recommendations$/);
  const movieId = match[1];
  ...
}
```

The idiomatic fix (already used for the season route in this same file):

```js
let match;
if ((match = pathname.match(/^\/api\/movies\/(\d+)\/recommendations$/))) {
  const movieId = match[1];
  ...
}
```
