# Player box redesign, anime catalog, and recommendations rails (v2)

This change replaces the standalone Player route with an inline PlayerBox on detail pages, adds an Anime section with tabbed infinite-scroll (trending/ongoing/top-rated), introduces "More Like This" / "Related Series" recommendations on detail pages, and extends the home page with "Ongoing Series" and "Trending Anime" rails. The v1 review raised four issues: hero randomization is now fixed with `useMemo` on both platforms, the "Ongoing" anime endpoint now includes `with_status: '0'` (Returning Series), the anime `ja`-only filter was acknowledged as intentional, and the double-regex pattern was noted as pre-existing.

**Watch for:** The `with_status: '0'` value passed to TMDB may not map to "Returning Series" — TMDB's discover API documents this parameter as a pipe-separated list where `0` means "Returning Series" but some community references use string values instead; verify this actually filters correctly in production (possible). The PlayerBox fallback state (no backdrop) renders an empty dark box with no textual hint — users without TMDB backdrop art see only a play button on black (confirmed).

**Verdict**: APPROVED

## High-level view

The PlayerBox implements the requested behavior: a 16:9 backdrop thumbnail with centered play icon that swaps to a VideoPlayer iframe on click. When no backdrop image exists, the fallback is a featureless dark rectangle — functional but could confuse users who don't realize the box is interactive.

The anime "ongoing" endpoint combines `with_status: '0'` with the 30-day `air_date.gte` window as belt-and-suspenders filtering. If TMDB respects the status parameter, the date window is redundant but harmless. If TMDB silently ignores `with_status`, the date window provides a safety net. The `ja`-only language filter is a deliberate trade-off to avoid Disney/Pixar contamination.

## PlayerBox fallback for missing backdrops

When `item.backdrop_url` is falsy:

```jsx
<div className="w-full h-full bg-background-elevated" />
```

The user sees a plain dark box with a floating play circle. No text, poster image, or icon indicating what content this represents. For the majority of popular TMDB content this won't trigger (backdrops are widely available), but for obscure titles or newly-added entries, the box offers no visual cue. Consider falling back to `item.poster_url` scaled to fill, or rendering the title overlaid on the dark background.

## TMDB `with_status` parameter semantics

The ongoing endpoint sends:

```js
{ with_genres: '16', with_original_language: 'ja', 'air_date.gte': thirtyDaysAgo, with_status: '0', sort_by: 'popularity.desc', page }
```

TMDB's `/3/discover/tv` accepts `with_status` as a pipe-separated list of integer codes: `0` = Returning Series, `1` = Planned, `2` = In Production, `3` = Ended, `4` = Cancelled, `5` = Pilot. The value `'0'` should be correct, but TMDB has been known to silently ignore unrecognized parameter formats. The `air_date.gte` window provides a fallback guarantee: even if status filtering fails, results are limited to recently-aired shows. Worth a manual test against the TMDB API to confirm the filter is actually applied.
