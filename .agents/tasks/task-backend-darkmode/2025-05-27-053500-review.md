# Backend CORS proxy and premium dark mode redesign

This change splits the frontend's direct dependency on vidapi.ru into a two-tier architecture: a Bun.serve() backend at `apps/server/` acts as a caching CORS proxy, and the React frontend now talks to that proxy instead of using Vite's dev proxy or direct calls. Alongside the architecture shift, every component and page in `apps/web/` is recolored from a white/blue light theme to a #0F0F0F/#1A1A1A/#6366F1 dark palette with glassmorphism header, shimmer loaders, and indigo glow cards. Deployment configs (render.yaml, vercel.json) are updated to wire both services together, and a root-level monorepo package.json orchestrates workspace scripts.

**Watch for:** Unbounded cache growth on the server will eventually OOM in production (confirmed). The `connect-src` CSP still hardcodes `http://localhost:3001` in the production HTML, which leaks dev infrastructure (confirmed). The frontend API URL fallback and the Vercel rewrite strategy are in tension — they can't both work correctly with the same build artifact (confirmed).

## High-level view

The backend server is a single-file Bun HTTP handler that strips `/api` from incoming paths, forwards to vidapi.ru, and caches responses in a Map with path-dependent TTLs (1h search, 24h lists, 7d details). There's no eviction policy, so the cache grows monotonically until the process restarts.

The frontend API client now uses `import.meta.env.VITE_API_URL || 'http://localhost:3001/api'` — an absolute URL baked at build time. This conflicts with Vercel's rewrite strategy: on Vercel the env var must NOT be set (so the frontend calls relative `/api/...` paths that the rewrite handles), but if unset the code falls back to localhost. These two approaches need reconciliation.

The dark mode uses consistent hex values across all components, but those values are hardcoded (`bg-[#1A1A1A]`) rather than referencing the semantic tokens defined in tailwind.config.js (`bg-surface`). Future palette changes require touching 17 files.

CORS is `Access-Control-Allow-Origin: *` with no rate limiting, making the server a publicly usable vidapi.ru cache relay.

<details>
<summary>Issues (6)</summary>

1. **Unbounded cache growth** — The in-memory Map never evicts expired entries proactively and has no size cap. Add a max-size LRU or periodic sweep to prevent OOM on long-running instances.
2. **CSP leaks localhost** — `connect-src` in index.html includes `http://localhost:3001`, which ships to production. Remove it or gate it behind a build-time conditional.
3. **Hardcoded hex vs. semantic tokens** — Tailwind config defines semantic color names (`surface`, `primary`, `text-secondary`) but components use raw hex (`#1A1A1A`, `#6366F1`). Migrate to `bg-surface`, `text-primary`, etc. for maintainability.
4. **Open CORS proxy without rate limiting** — `Access-Control-Allow-Origin: *` with no request throttling means anyone can abuse this server as a free vidapi.ru relay. Add origin allowlist or rate limiting.
5. **Fallback URL in production builds** — If `VITE_API_URL` is unset at build time, the frontend bakes in `http://localhost:3001/api` which silently fails in production. Make the env var required or fail loudly.
6. **Vercel/env-var strategy conflict** — vercel.json rewrites `/api/*` to the Render backend, but the frontend code uses an absolute URL when `VITE_API_URL` is set. These two strategies can't coexist in the same build. Pick one: either always use relative `/api` paths and let the hosting layer route, or always use the env var and remove the rewrite.

## Caching proxy without eviction

The server stores every unique `pathname + search` combination in a Map. Expired entries are only removed on read (`getCached` deletes stale entries when accessed), but entries that are never re-requested stay in memory forever. With 7-day TTL on detail pages and an ever-growing catalog, this is a slow memory leak.

```js
// This only cleans up when the same key is requested again:
if (Date.now() > entry.expiresAt) {
  cache.delete(key);
  return null;
}
```

A `setInterval` sweep every 5 minutes, or switching to an LRU with a hard size cap (e.g. 10,000 entries), would bound memory usage. The `/health` endpoint exposes `cache_size` for monitoring but there's no self-healing.

## CSP and deployment wiring

The Content-Security-Policy meta tag in `index.html` is a single static string that ships to all environments:

```
connect-src 'self' https://vidapi.ru https://vaplayer.ru http://localhost:3001 https://hijistream-api.onrender.com;
```

`http://localhost:3001` in production signals internal architecture to anyone inspecting the page source and adds noise to security audits.

The Vercel deploy rewrites `/api/:path*` to the Render backend, so Vercel-hosted users pay cross-cloud latency on every API call. If the Render free tier cold-starts (common after 15 min inactivity), the first request can take 30+ seconds with no user-facing retry prompt.

## Frontend API URL conflict

```js
const BASE_URL = import.meta.env.VITE_API_URL || 'http://localhost:3001/api';
```

This is evaluated at build time. On Render, the env var is set correctly. On Vercel, the rewrite in vercel.json handles routing — but that only works if the frontend calls `/api/...` (relative). If `VITE_API_URL` is set on Vercel, the frontend bypasses the rewrite and calls the Render backend directly (adding CORS and latency). If it's unset, the fallback is localhost (broken).

The cleanest fix: change the fallback to `/api` (relative) instead of `http://localhost:3001/api`. Then Vercel's rewrite works, Render's env var works, and local dev can set the env var explicitly.

## Dark mode token drift

tailwind.config.js defines semantic tokens:

```js
colors: {
  background: '#0F0F0F',
  surface: '#1A1A1A',
  'surface-elevated': '#262626',
  primary: '#6366F1',
  'text-secondary': '#A1A1A1',
  'text-muted': '#6B6B6B',
}
```

But components use `bg-[#1A1A1A]` instead of `bg-surface`, `text-[#A1A1A1]` instead of `text-text-secondary`. The config is documentation rather than a single source of truth. Changing the accent color would require touching every component file.

## Open relay posture

`Access-Control-Allow-Origin: *` with no rate limit or API key means any third-party site can point at this endpoint. On a paid Render plan with bandwidth limits, abuse translates directly to billing surprises.
