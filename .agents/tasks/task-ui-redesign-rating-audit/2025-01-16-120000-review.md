# Mobile UI polish pass and i18n bug fixes

The change tightens the visual density of the mobile app's Home screen, bottom navigation, and category pages while fixing several i18n gaps in components that had hardcoded English strings. The HeroBanner drops from 55% to 40% viewport height with a single overlay replacing the triple-overlay stack, the tab bar switches from dark-gray/red to true-black/white, and genre/country pages get refined headers. A bug audit fixes TVFocusable's forced minimum sizing, adds missing i18n keys to all 7 locales, and reduces ContentGrid padding.

**Watch for:** A hardcoded `"Season {i + 1}"` string remains in EpisodeList despite the i18n cleanup (confirmed). ErrorState still has a hardcoded English fallback `'An unexpected error occurred'` that won't translate (confirmed). The HeroBanner height is computed once at module load via `Dimensions.get('window')` — pre-existing, but now more visible at 40% since orientation/foldable changes won't update it (possible).

## High-level view

The visual changes are conservative — colors, heights, padding, border widths. Nothing touches data flow, navigation logic, or API calls. The HeroBanner simplification removes two redundant overlay Views and collapses a gradient-stacking trick into a single semi-transparent block covering the bottom 60% of the backdrop. The tab bar color swap (red active → white active) removes the only brand-color accent from persistent navigation — worth confirming that's intentional.

The i18n fixes wire `useTranslation()` into EpisodeList and ErrorState, with new keys propagated to all 7 locale files. However, the cleanup is incomplete: one hardcoded English string survived in EpisodeList's season selector, and ErrorState's fallback message for null errors is still English-only.

The TVFocusable fix is the most impactful behavioral change. Removing `minWidth: 80` / `minHeight: 80` from the default container style means every TVFocusable-wrapped element sizes itself naturally. The border now only appears on focus. But the removal of any default min-size means TV remote users may encounter very small focus targets if a wrapped child doesn't set its own dimensions.

## HeroBanner overlay simplification

The old approach stacked three `View`s — a transparent fill, a 150px semi-transparent band, and an 80px near-opaque band — to simulate a gradient without `expo-linear-gradient`. The replacement is a single View anchored to the bottom, 60% tall, at `rgba(10,10,10,0.75)`. This trades the multi-stop effect for a hard edge. On bright backdrops the transition from image to overlay will be more visible as a line, whereas the old stacking softened it.

## Incomplete i18n in EpisodeList

The diff shows three i18n fixes inside EpisodeList — the heading, empty-state text, and "Play Season" button all use `t()`. But the season selector buttons still render:

```jsx
<Text ...>Season {i + 1}</Text>
```

The `player.season` key exists in all 7 locale files. This is a straightforward miss: `{t('player.season')} {i + 1}` would complete the fix.

## TVFocusable sizing trade-off

The old style applied `minWidth: 80, minHeight: 80, borderWidth: 3` unconditionally, bloating ContentCards and forcing visible borders on non-focused elements. The fix removes the min dimensions and moves the border to the `focused` state only.

The risk: some wrapped children are quite small. The EpisodeList play button is 36×36, and ButtonRow items set `minWidth: 100, minHeight: 40`. On a TV remote interface where the focusable area equals the rendered size, sub-48dp targets become difficult to navigate to. Worth auditing which wrapped children fall below that threshold.

## Genre/country page typography divergence

Both genre and country pages removed the `typography` import and replaced `...typography.title` with explicit `fontSize`/`fontWeight` values. This creates a divergence: future changes to the shared typography tokens won't propagate to these screens. If `typography.title` is ever updated for a design system refresh, these pages will be out of sync.
