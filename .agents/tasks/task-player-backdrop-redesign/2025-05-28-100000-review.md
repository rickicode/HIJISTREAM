# Backdrop image relocated from DetailHero to PlayerBox

The backdrop/cover image previously rendered as a full-width background in the DetailHero component (both web and mobile) has been moved into the PlayerBox area. On web, PlayerBox now shows the backdrop as an `object-cover` background with a gradient overlay and centered play button when not playing, transitioning to the VideoPlayer when active. On mobile, a new PlayerBox component provides the same visual with a 16:9 ImageBackground. DetailHero on both surfaces is reduced to a clean info panel (poster, metadata, overview) without the large cinematic backdrop. TVDetail on web now uses the shared PlayerBox component instead of rendering VideoPlayer inline, matching MovieDetail's pattern.

**Watch for:** Static `Dimensions.get('window')` in the mobile PlayerBox won't adapt to orientation changes or split-screen (confirmed). The player screen uses `poster_url` as background while PlayerBox uses `backdrop_url` — visual inconsistency on content that has different poster vs backdrop images (confirmed). Both mobile detail screens pass `onPlay` to DetailHero, producing a redundant second play button below the PlayerBox play button (confirmed).

## High-level view

The web surface gains a backdrop image in PlayerBox's idle state and strips the 450px backdrop from DetailHero. TVDetail is refactored to use PlayerBox identically to MovieDetail, consolidating two divergent player-rendering paths into one. The scroll-to-player behavior shifts from a ref-based `scrollIntoView` to `window.scrollTo({ top: 0 })`, which works because PlayerBox is always the first element in the page content.

The mobile surface introduces a new PlayerBox component that captures the backdrop display responsibility previously held by DetailHero's ImageBackground section. Both movie and TV detail screens render PlayerBox above DetailHero. The player screen wraps its VideoPlayer in an ImageBackground with 85% opacity overlay, though it uses `poster_url` rather than `backdrop_url`, creating a visual discontinuity on transition.

## Duplicate play affordances on mobile

Both the movie and TV detail screens pass `onPlay` to DetailHero:

```jsx
<PlayerBox item={movie} onPlay={handlePlay} />
<DetailHero item={movie} type="movie" onPlay={handlePlay} />
```

DetailHero renders a "Play" button when `onPlay` is provided. This means users see two distinct play triggers — the centered circle in PlayerBox and the white rectangular button in the info section. On web, DetailHero receives `onPlay` for TV (intentionally, since episodes need a general play entry point alongside the episode list) but movies don't pass it — the MovieDetail page only gives `onPlay` to PlayerBox. On mobile, both components always receive the same handler regardless of content type. If the intent is to have PlayerBox own the primary play action, DetailHero should not receive `onPlay` when PlayerBox is present, or the mobile DetailHero should conditionally suppress the button.

## Static screen dimensions

```jsx
const { width: screenWidth } = Dimensions.get('window');
const playerHeight = screenWidth * (9 / 16);
```

This is evaluated at module load time. On phones that support rotation or tablets in split-screen, the PlayerBox will retain its original dimensions after the window resizes. The fix is straightforward: replace with the `useWindowDimensions()` hook inside the component body and derive `playerHeight` from it.

## Backdrop source inconsistency between PlayerBox and player screen

The mobile PlayerBox resolves its image as `item.backdrop_url || item.poster_url`, preferring the wider backdrop. The player screen's ImageBackground uses `poster_url` directly from route params:

```jsx
<ImageBackground source={{ uri: poster_url }} style={styles.container} resizeMode="cover">
```

For content where `backdrop_url` and `poster_url` differ significantly (e.g., a landscape cinematic shot vs a portrait poster), the user sees the backdrop abruptly switch to the poster when tapping play. Passing `backdrop_url` through route params and preferring it in the player would maintain continuity.

## Web PlayerBox fallback behavior

When `item.backdrop_url` is falsy, the web PlayerBox skips the `<img>` but still renders the gradient overlay div and the play button over a plain black container. The mobile version falls back to `item.poster_url` with the `||` operator. Adopting the same pattern on web:

```jsx
const imageUrl = item.backdrop_url || item.poster_url;
```

would ensure both surfaces show meaningful imagery regardless of which URL is available.
