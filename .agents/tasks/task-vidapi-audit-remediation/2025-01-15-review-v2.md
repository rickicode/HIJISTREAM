# VidAPI embed URL compliance, player skinning, and content filtering (v2)

This change fixes the embed URL query parameter from `?t=` to `?resumeAt=` across web and mobile, adds `skin=netflix` and `ds_lang` parameters to all player embed URLs, introduces a topbar EN/ID language selector on both surfaces, and applies a three-layer invalid-item filtering strategy with aligned predicates. The v2 pass addresses all five issues from the v1 review: reactive language updates via custom event, filter predicate alignment, test imports of production code, mobile player language dependency, and URL encoding in mobile player.js.

**Watch for:** The mobile `ContentGrid` uses `item.tmdb_id` as `keyExtractor` but the filter now requires `item.id` — if an item has `tmdb_id` but not `id`, it will be filtered out before reaching the keyExtractor, so this is safe but the semantic mismatch is confusing (confirmed). The web `Layout.jsx` language buttons call `setLanguage()` which dispatches a `language-change` event, but `Layout` itself doesn't listen for that event — it sets local state directly. If language is changed from another tab/window via storage events, Layout won't reflect it (possible, low impact).

**Verdict**: APPROVED

## High-level view

The five v1 issues are resolved correctly. Web detail pages now listen for a `language-change` custom event via a `_langVersion` state counter that forces re-render, causing `getDsLang()` to return the fresh value when the embed URL is computed in the component body.

Both ContentGrid components (web and mobile) now use `item && item.id && item.title` — the same strict AND predicate as `api.js` and the server. The three filtering layers are aligned: server, API client, and render component all reject items missing `id` or `title`.

The `transform.test.js` file now imports `filterValidItems` from `../src/utils/api` directly, so tests exercise the production code path.

The mobile `player.jsx` fetches `dsLang` into component state via a separate `useEffect` and includes `dsLang` in the URL-building effect's dependency array. When language resolves from AsyncStorage, the URL is rebuilt.

Mobile `player.js` now wraps all parameter values in `encodeURIComponent()`, closing the latent fragility gap for non-ASCII or reserved-character values.

2. **Mobile language change doesn't propagate to an open player** (confirmed, accepted trade-off) — The mobile player reads `dsLang` on mount via `useEffect([], ...)` and includes `dsLang` in the URL-build dependency array. But `dsLang` is only fetched once on mount — there's no subscription to storage changes. If the user changes language in the tab bar and then goes back to an already-mounted player, the URL won't update. Acceptable given Expo's screen lifecycle (player unmounts on back-navigation), but worth documenting.

## Reactive language on web via custom event

The fix introduces a `_langVersion` state counter in both `MovieDetail.jsx` and `TVDetail.jsx`:

```js
const [_langVersion, setLangVersion] = useState(0);

useEffect(() => {
  const onLangChange = () => setLangVersion(v => v + 1);
  window.addEventListener('language-change', onLangChange);
  return () => window.removeEventListener('language-change', onLangChange);
}, []);
```

The counter's only purpose is to force a re-render so `getDsLang()` is called fresh in the component body. The `setLanguage()` function dispatches the event:

```js
export function setLanguage(lang) {
  if (SUPPORTED_LANGS.includes(lang)) {
    localStorage.setItem(STORAGE_KEY, lang);
    window.dispatchEvent(new Event('language-change'));
  }
}
```

This closes the loop: topbar button → `setLanguage()` → event dispatch → detail page re-render → fresh `getDsLang()` in embed URL. The pattern relies on `window` event propagation which won't work across browser tabs (localStorage `storage` events would, but that's a minor edge case).

## Mobile player dsLang dependency

The mobile player separates language fetching from URL building:

```js
const [dsLang, setDsLangState] = useState(null);

useEffect(() => {
  getDsLang().then(setDsLangState);
}, []);

useEffect(() => {
  async function buildUrl() {
    const options = { skin: 'netflix', dsLang: dsLang };
    // ... build URL
  }
  buildUrl();
}, [type, id, season, episode, contentId, dsLang]);
```

Including `dsLang` in the dependency array means the URL rebuilds when the async read completes. However, there's no subscription mechanism — if language changes while the player is mounted (unlikely in normal flow but possible if screens are kept alive), the URL remains stale until unmount/remount.

## ContentGrid keyExtractor mismatch

The mobile ContentGrid's `keyExtractor` reads `item.tmdb_id`:

```js
keyExtractor={(item) => String(item.tmdb_id)}
```

The filter guarantees `item.id` exists but doesn't guarantee `item.tmdb_id`. In the current TMDB-backed data model, `id` and `tmdb_id` are always the same value (assigned in the server transform's `transformMovieListItem`). If a non-TMDB data source is ever added, items could pass the filter with `id` and `title` but produce `"undefined"` keys, causing React reconciliation bugs. Using `item.id` as the key would be more defensive.
