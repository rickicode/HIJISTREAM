# Netflix-style UI redesign across web and mobile (v2)

The v1 review raised six issues; four have been addressed cleanly. CVA is gone from package.json, ContinueWatchingRail now delegates to ContentRail, hero selection randomizes from the first five trending items, and mobile EpisodeList renders an empty-state message instead of fake interactive episodes. The two deferred items (mobile gradient banding, token migration) are acknowledged and reasonable to ship as-is.

**Watch for:** Hero randomization runs on every render without memoization, causing the featured item to change each time React re-renders the home page (confirmed). The `watchProgress` items passed to ContentRail on web lack `id` or `tmdb_id`, which is used as the React `key` — if the storage format doesn't include those fields, the rail will key every card as `undefined` (possible).

**Verdict**: APPROVED

## High-level view

The hero randomization fix introduces a subtle re-render instability: `Math.random()` runs during render without `useMemo` or `useRef`, so any parent state change (e.g., query cache update, watch-progress reload) picks a new hero. On web this is tolerable since `useQuery` won't trigger re-renders once data is stable, but on mobile the `loadProgress` callback and FlatList lifecycle make it more likely to fire.

## Hero selection re-renders

Both web and mobile compute the hero inside the render body:

```jsx
const heroItem = movieItems.length > 0
  ? movieItems[Math.floor(Math.random() * Math.min(movieItems.length, 5))]
  : null;
```

On mobile, `HomeScreen` calls `loadProgress()` in a `useEffect` that updates `watchProgress` state, which triggers a re-render after the initial mount — picking a new random hero even though the movie data hasn't changed. The fix:

```jsx
const heroItem = useMemo(() => {
  if (movieItems.length === 0) return null;
  return movieItems[Math.floor(Math.random() * Math.min(movieItems.length, 5))];
}, [movieItems]);
```

This pins the selection until the `movieItems` reference changes (i.e., a new fetch completes).

## Watch progress key stability

`ContentRail` uses this key extractor:

```jsx
items.map((item) => (
  <div key={item.id || item.tmdb_id} className="...">
```

The web `getAllWatchProgress()` utility reads from localStorage. If the stored shape uses a different identifier field (e.g., `contentId`, `imdb_id`) without also including `id` or `tmdb_id`, the key resolves to `undefined` for every item, causing React to warn and potentially mis-reconcile cards during scroll updates.
