# Netflix-style UI redesign across web and mobile

The entire HIJISTREAM front-end — 8 web components, 7 web pages, 10 mobile components, and 8 mobile screens — has been rewritten with a Netflix-inspired dark design language. The approach replaces the existing indigo/dark-gray palette with Netflix tokens (#141414 background, #E50914 primary red, #46d369 rating green), introduces new compositional primitives (HeroBanner, ContentRail), and adds a shared `cn()` utility from the shadcn/ui ecosystem. Data-fetching, routing, and watch-progress logic are explicitly preserved unchanged.

**Watch for:** The `ContinueWatchingRail` in `Home.jsx` duplicates the entire ContentRail scroll-arrow pattern inline rather than reusing the component (confirmed). The mobile HeroBanner gradient is faked with stacked opaque `View` layers, producing visible banding rather than smooth gradients on many Android devices (likely). `class-variance-authority` is installed as a dependency but never imported anywhere in the diff (confirmed).

## High-level view

The design system foundation lands three new npm packages (`class-variance-authority`, `clsx`, `tailwind-merge`) and a `cn()` utility, but only two of the three see actual use — CVA is dead weight in the bundle. The Tailwind config restructures color tokens from flat names (`surface`, `text-primary`) to nested objects (`background.card`, `muted.foreground`), which means any pre-existing consumer referencing old tokens will silently get Tailwind's default value or no style at all.

The web redesign introduces two new primitives: `HeroBanner` (full-bleed featured item with gradient overlays and action links) and `ContentRail` (horizontal scroll with hover-visible chevron arrows). The home page composes these with TanStack Query data to produce the Netflix "hero + rails" layout. Existing grid-based browse pages and detail pages keep their query logic intact but get the new dark chrome.

The mobile redesign mirrors the web's design language through a `theme.js` token file that all components import. Gradient overlays are approximated with layered semi-transparent Views since React Native lacks CSS gradients natively — this produces visible banding on many devices. The mobile EpisodeList generates fake interactive episodes when data is empty, which can send users to the player with invalid identifiers.

The `ContinueWatchingRail` in web's Home page is a hand-rolled copy of ContentRail rather than a reuse of it, duplicating the scroll-arrow markup and scroll logic.

## Unused class-variance-authority dependency

The `package.json` adds `"class-variance-authority": "^0.7.1"` and the lockfile resolves it, but no file in the diff imports `cva` or anything from the package. The stated design intent was "CVA variants" for component styling, yet every component uses raw `cn()` calls with string literals instead. This adds ~7 KB (minified) to the bundle for no behavioral gain. Either use it in ContentCard/TabNavigation where variant patterns would fit, or remove it.

## ContinueWatchingRail vs ContentRail duplication

`Home.jsx` defines a local `ContinueWatchingRail` component that reimplements the identical scroll-arrow pattern already encapsulated in `ContentRail`:

```jsx
// ContinueWatchingRail (Home.jsx, lines 20-60)
const scroll = (direction) => { ... };
// ... chevron buttons, scrollRef, overflow-x-auto

// ContentRail.jsx (identical pattern)
const scroll = (direction) => { ... };
// ... chevron buttons, scrollRef, overflow-x-auto
```

The only behavioral difference is that `ContinueWatchingRail` passes a `watchProgress` prop to `ContentCard`. ContentRail already renders ContentCard and could accept the items shaped to include `percentage`. This duplication means scroll bugs would need fixing in two places.

## Mobile gradient approximation

Both `HeroBanner` and `DetailHero` on mobile use three stacked `View` layers with increasing opacity (`rgba(20,20,20,0.1)`, `0.6`, `0.9`) to simulate a gradient fade from image to background:

```
gradientOverlay1 — full-fill, rgba(20,20,20,0.1)
gradientOverlay2 — bottom 200px, rgba(20,20,20,0.6)
gradientOverlay3 — bottom 100px, rgba(20,20,20,0.9)
```

`expo-linear-gradient` (already compatible with Expo Router setups) would eliminate the banding with a single component and smooth interpolation. On AMOLED screens with true black the banding is especially visible in the 0.1-to-0.6 transition region.

## Token restructuring and silent breakage risk

The Tailwind config moves from flat color names to nested objects:

- `background` was `'#0F0F0F'` (string), now `{ DEFAULT, elevated, card }`
- `primary` was `'#6366F1'` (string), now `{ DEFAULT, hover }`
- `surface`, `surface-elevated`, `text-primary`, `text-secondary`, `text-muted`, `primary-hover`, `border-hover` — all removed entirely

Any class like `bg-surface` or `text-text-primary` used elsewhere in the codebase (or in a co-developed branch) will now resolve to nothing. The build succeeds because Tailwind doesn't error on unknown utility classes — it just doesn't emit them.

## HeroBanner hero selection is deterministic

Both web and mobile pick `heroItem = movieItems[0]` — the first trending movie. The feature spec described "a random trending item" for variety. Users see the same hero on every visit until the API rotates its ordering (typically daily for TMDB trending).

## Mobile EpisodeList generates placeholder episodes when data is empty

When `episodes` is not a populated array, the mobile `EpisodeList` generates 10 synthetic `{ episode: N, title: "Episode N" }` placeholders and renders them with functional play buttons that trigger `onPlayEpisode`. Pressing play on a placeholder episode will attempt to navigate to a player with potentially invalid season/episode identifiers. The web version handles this case with an empty-state message and a "Play Season N" button — the asymmetry means mobile users may hit player errors that web users won't.
