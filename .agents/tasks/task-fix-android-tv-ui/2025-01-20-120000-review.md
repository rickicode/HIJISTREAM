# Android TV fullscreen player and D-pad navigation

This change makes the streaming app's existing UI usable on Android TV by adding two capabilities: a fullscreen video player with overlay controls (back + subtitles) that auto-hide after 5 seconds, and D-pad focus management across browse screens so the first focusable item receives initial focus and episode rows are entirely focusable rather than requiring the user to navigate into a tiny play icon. The focus ring was also changed from white to the brand's primary red, with a wider border and larger shadow. A redundant Language/Globe button was removed from the TV top nav since language settings are reachable from the profile screen.

**Watch for:** The player screen renders two independent back buttons on TV — one in `player.jsx` (always visible, receives preferred focus) and one inside `VideoPlayer.jsx` (auto-hides after 5 seconds) — creating a confusing D-pad order and duplicated navigation [confirmed]. Once the VideoPlayer controls auto-hide, there is no way for the user to re-show them via D-pad interaction [confirmed]. The Subtitles button has a no-op handler (`() => {}`) that will confuse users who focus and press it [confirmed].

## High-level view

The player screen gains a TV overlay system, but the implementation splits back-button responsibility between the parent route (`player.jsx`) and the child component (`VideoPlayer.jsx`). Both render a `ChevronLeft` back button absolutely positioned in the top-left corner, but with different visibility lifecycles and different `hasTVPreferredFocus` values. The parent's button is always visible and grabs focus; the child's button hides after 5 seconds with no mechanism to resurface it.

D-pad focus seeding is propagated from the home screen down through ContentRail and ContentGrid by passing `hasTVPreferredFocus` to the first item in each list. DetailHero, EpisodeList, and ContentGrid each conditionally enlarge tap targets and spacing on TV using the `useIsTV` hook.

The focus ring change from white border to primary-red border is a global visual change affecting every TVFocusable instance app-wide. The `shadowRadius` and `shadowOpacity` increases have no effect on Android (only `elevation` is rendered), so the shadow improvement is dead code on the target platform.

1. **Duplicate back buttons in player** — `player.jsx` renders a permanently visible back button with `hasTVPreferredFocus={true}`, while `VideoPlayer.jsx` renders its own back button in the overlay that hides after 5 seconds. Remove one; the parent's always-visible button is likely the one to keep, with the VideoPlayer overlay reserved for playback controls only.
2. **Controls cannot be re-shown** — Once `showControls` goes `false` in `VideoPlayer.jsx`, no D-pad event or timer resets it to `true`. Add a focus/keypress listener that re-shows controls on any D-pad interaction.

4. **Shadow styles ignored on Android** — `shadowOpacity`, `shadowRadius`, `shadowOffset` in `ringWrapper` are iOS-only. The focus ring on Android TV relies solely on `elevation: 12` set conditionally in the component, so the shadow visual upgrade has no effect on the target platform.
5. **`hasTVPreferredFocus` on first rail item is coarse** — In `home.jsx`, the flag is passed to the first `ContentRail` that renders (trending movies), which seeds focus on the first movie card. If "Continue Watching" appears above it (non-empty progress), focus still lands on the movie rail, skipping the resume rail.

## Dual back-button conflict in the player

`player.jsx` adds an always-visible `TVFocusable` back button at `top: 24, left: 24` with `hasTVPreferredFocus={true}`. Separately, `VideoPlayer.jsx` renders its own overlay containing a back button at `paddingTop: 20, paddingHorizontal: 24` with `hasTVPreferredFocus={false}`. Both call `router.back()`. On mount, the D-pad focus will jump to the parent's button (preferred focus = true), and the VideoPlayer's back button sits directly underneath it visually but in a different Z-order layer. After 5 seconds the VideoPlayer overlay hides, but the parent's button remains. The problem manifests in the first 5 seconds when both are simultaneously visible and focusable, making D-pad navigation unpredictable.

The intended architecture appears to be: parent (`player.jsx`) owns the always-visible escape hatch, and `VideoPlayer` owns transient playback controls. If that's the case, the VideoPlayer overlay should not contain a back button — or the parent's back button should be removed and the overlay should stay visible until the user explicitly dismisses it.

## Controls auto-hide with no re-show path

The `useEffect` in `VideoPlayer.jsx` sets a 5-second timeout that flips `showControls` to `false`. Nothing in the component ever sets it back to `true`. On TV the only input is D-pad events. Since `pointerEvents="box-none"` is set on the overlay container, D-pad focus events on the hidden buttons won't fire because the overlay is unmounted when `showControls` is `false`.

The fix is to listen for any `onFocus` or `onKeyDown` event on the player container and reset `showControls` to `true`, which re-triggers the 5-second auto-hide timer via the existing effect.

## Subtitles button wired to nothing

```jsx
<TVFocusable
  onPress={() => {}}
  style={styles.tvControlButton}
  accessibilityLabel="Subtitles"
>
  <Subtitles size={24} color="#FFFFFF" />
</TVFocusable>
```

On TV, where navigation is expensive (you can't just tap elsewhere), a no-op button is worse than a missing button — it trains the user that the remote isn't working. Either remove it until subtitle toggling is implemented, or at minimum show a toast indicating the feature isn't available.

## Focus ring shadow on Android TV

The `ringWrapper` style changes `shadowOpacity` to 1 and `shadowRadius` to 20. React Native on Android does not render iOS-style shadows — it uses `elevation` only. The TVFocusable component already applies `elevation: 12` conditionally when focused on Android, so the ring is visible via elevation, but the shadow radius/opacity changes are dead code on the target platform.

## D-pad focus seeding strategy

`home.jsx` passes `hasTVPreferredFocus={isTV}` to the first `ContentRail` in its render list, which happens to be the trending-movies rail. However, the home screen conditionally renders a "Continue Watching" rail above the movies rail when `watchProgress.length > 0`. That rail doesn't receive `hasTVPreferredFocus`, so initial D-pad focus skips it and lands on the second visual row — the topmost interactive content should receive initial focus instead.
