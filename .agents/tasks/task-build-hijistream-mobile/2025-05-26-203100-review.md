# Expo mobile/TV app for HIJISTREAM (v2)

Five of the seven v1 issues have been fixed: WebView `postMessage` bridge injected, `ContentGrid` uses `useWindowDimensions()`, home screen uses section-based `FlatList`, Zustand removed from dependencies, `tvParallaxProperties` removed from `TVFocusable`. Two items intentionally unchanged (dual-cache matching web app, TanStack Query preferred over Zustand). Two new concerns remain after verifying the fixes.

**Watch for:** The `injectedJavaScript` bridge patches `window.postMessage` but won't intercept messages posted from iframes within the embed player — progress tracking likely still broken (confirmed). The home screen's section-based `FlatList` still nests horizontal `FlatList`s as render items, producing the same VirtualizedList nesting warning (confirmed).

## High-level view

The `postMessage` bridge intercepts calls at the top window level, but embed players typically post messages from an iframe to their parent via `window.parent.postMessage`. That arrives as a `message` event on the top frame — it doesn't invoke the patched `window.postMessage`. Without a `message` event listener, progress events from the iframe player never reach `onMessage`.

The home screen replaced the outer `ScrollView` with a `FlatList` rendering section objects, but each section still returns a horizontal `FlatList`. React Native's nesting detection triggers on any VirtualizedList inside another VirtualizedList regardless of whether the outer is a ScrollView or FlatList. The inner lists are capped at 8 items — switching them to `ScrollView horizontal` eliminates the warning with no performance cost.

## postMessage bridge: top-frame-only interception

The injected script in `VideoPlayer.jsx`:

```javascript
(function() {
  var originalPostMessage = window.postMessage;
  window.postMessage = function(data, origin) {
    if (window.ReactNativeWebView && window.ReactNativeWebView.postMessage) {
      window.ReactNativeWebView.postMessage(typeof data === 'string' ? data : JSON.stringify(data));
    }
    originalPostMessage.call(window, data, origin);
  };
})();
```

VidAPI's embed page at `vaplayer.ru/embed/...` likely loads its video player inside an iframe (standard practice for embed players). When the iframe player detects a progress event, it calls `window.parent.postMessage(data, '*')`. That call arrives as a `message` event on the top frame's `window` — it doesn't invoke `window.postMessage` on the top frame. The current patch only intercepts outgoing calls from the top frame, not incoming messages from child frames.

The fix: add a `message` event listener that catches cross-frame messages and relays them:

```javascript
window.addEventListener('message', function(event) {
  if (window.ReactNativeWebView && event.data) {
    window.ReactNativeWebView.postMessage(
      typeof event.data === 'string' ? event.data : JSON.stringify(event.data)
    );
  }
});
```

Without this, the `handleMessage` callback never fires for progress events originating from the iframe player, meaning watch progress is never saved and "Continue Watching" remains permanently empty.

## Home screen: FlatList-as-section-container still triggers nesting warning

The refactored home screen:

```javascript
<FlatList
  data={sections}
  keyExtractor={(item) => item.key}
  renderItem={renderSection}  // each renderSection returns a horizontal FlatList
/>
```

React Native's VirtualizedList nesting detection checks whether a VirtualizedList is rendered inside another VirtualizedList's context — it doesn't distinguish between `ScrollView` and `FlatList` as the outer container. The warning persists because both `FlatList` (outer) and `FlatList` (inner horizontal) are VirtualizedLists.

Since the horizontal lists are capped at 8 items (`movies.slice(0, 8)`), virtualization provides no benefit. Replacing the inner `FlatList`s with `<ScrollView horizontal>` eliminates the warning without any performance cost.
