# Complete HIJISTREAM web app scaffold and implementation

The change delivers a full React + Vite video streaming SPA from zero: routing, caching layer, API client for vidapi.ru, Zustand stores, and nine reusable components assembled into seven pages (Home, Movies, TV, MovieDetail, TVDetail, Player, Search). It uses Bun for package management, Tailwind with a design-system token set, React Query for data fetching with infinite scroll, and iframe embeds from vaplayer.ru for playback. Production polish includes keyboard shortcuts, code splitting via `React.lazy`, document title management, and a cache-clear button.

**Watch for:** Missing Content Security Policy meta tag required by the TDD (confirmed). The "Continue Watching" section constructs cards from watch-progress entries that lack actual content metadata (title, poster), so they render with no image and a TMDB ID as the title (confirmed). The `EpisodeList` hard-codes 10 episodes per season with no fetched data, which makes the entire TV episode browsing experience fabricated rather than data-driven (confirmed). Search results are all typed as "movie" regardless of actual content type, so TV shows in search link to wrong routes (confirmed). The Zustand stores are defined but never consumed — all data flows through React Query directly, making them dead code (confirmed).

## High-level view

The caching system implements a localStorage-based TTL cache that pre-empts React Query's own built-in caching. Both layers cache the same data independently — React Query manages staleness in memory while `CacheManager` duplicates it to disk — but they never coordinate, meaning cache invalidation requires clearing both separately.

Security posture is incomplete: the TDD mandates a Content Security Policy restricting `frame-src`, `img-src`, and `script-src`, but the shipped `index.html` contains no CSP meta tag. The iframe embeds from `vaplayer.ru` accept `postMessage` events without origin validation, which is a cross-origin messaging gap.

The "Continue Watching" feature on Home reads localStorage progress entries, but those entries only contain an ID, time, duration, and percentage — never the content title or poster URL. The resulting cards render a TMDB ID as the title with no image, which is a broken user experience.

TV episode browsing is entirely fabricated: `EpisodeList` renders a hardcoded 10 episodes per season regardless of actual data. The TDD specifies an episodes array in the TV detail response, but nothing in the code fetches or renders real episode metadata.

The Zustand stores (`contentStore`, `playerStore`) are defined and imported but functionally dead. All data flows through React Query hooks; no component reads from or writes to the content store. The player store's `setWatchProgress` is never called from the `VideoPlayer` component — progress is saved directly via the `player.js` utility instead.

## Missing Content Security Policy

The TDD (Section 10.1) specifies a CSP meta tag restricting `frame-src` to `vaplayer.ru`, `img-src` to `image.tmdb.org` and the VidAPI domains, and `script-src` to `'self' 'unsafe-inline'`. The shipped `index.html` has OG meta tags and a description but no CSP. This means the app will accept frames, images, and scripts from any origin in production.

```html
<!-- Required but absent from index.html -->
<meta http-equiv="Content-Security-Policy"
      content="default-src 'self';
               img-src 'self' https://image.tmdb.org https://vidapi.ru https://vaplayer.ru;
               frame-src https://vaplayer.ru;
               script-src 'self' 'unsafe-inline';
               style-src 'self' 'unsafe-inline';">
```

## postMessage origin not validated

In `VideoPlayer.jsx`, `handleMessage` processes incoming `postMessage` events without checking `event.origin`. Any page that can reference this app in an iframe (or any other frame on the same page) can inject fake player events to corrupt watch progress data. The fix is a single guard at the top of `handleMessage`:

```javascript
if (event.origin !== 'https://vaplayer.ru') return;
```

## Continue Watching renders broken cards

`Home.jsx` calls `getAllWatchProgress()` which returns entries shaped as `{ id, time, duration, percentage, updatedAt }`. It then constructs a fake item:

```javascript
{ tmdb_id: item.id, title: item.id, poster_url: '', ...item }
```

This means the card's title is a raw ID string like `tt1517268` and the poster is an empty-string src (which triggers a broken-image load). To fix this, either:
- Persist content title and poster_url alongside progress in `saveWatchProgress`, or
- Resolve progress IDs against the API or a separate metadata cache before rendering.

## Hardcoded episode fabrication

`EpisodeList.jsx` accepts a `seasons` count and always renders exactly 10 episodes per season with generic labels ("Episode 1", "Episode 2", ...). The TDD specifies the TV detail response includes an `episodes` array with per-episode titles and thumbnails. The component should accept and render actual episode data from the API response rather than fabricating placeholders.

## Dual caching layers compete

React Query uses `staleTime: 5 * 60 * 1000` (5 minutes) and in-memory caching. The custom `CacheManager` uses localStorage with TTLs of 1h–7d. On a cache-hit path, `fetchWithCache` returns synchronously from localStorage before React Query ever sees a fetch. This works for initial loads, but the "Clear Cache" footer button does `localStorage.clear()` + `window.location.reload()` — the reload is necessary because React Query's in-memory cache is not cleared. This is a brute-force workaround for lack of coordination.

The simplest alignment: use React Query as the sole caching orchestrator and make `fetchWithCache` a pure fetch function, or make `CacheManager` a persistence adapter that React Query drives via a custom `queryFn` wrapper.

## Search type detection gap

In `Search.jsx`, all results are passed to `ContentGrid` with `type="movie"`. If the search API returns TV shows (which it does — the VidAPI search endpoint returns mixed results), those items will be rendered with links to `/movies/:id` instead of `/tv/:id`. The fix: determine type from the item data (e.g., `item.media_type` or presence of `seasons` field) and pass it per-item, or distinguish at the ContentGrid level.

## Keyboard shortcuts coverage

The PRD (Section 3.2.2) specifies: arrow-key grid navigation, Enter to select, Escape to go back, Space for play/pause, F for fullscreen. The implementation provides:
- Escape (global, via `useKeyboardShortcuts` in Layout)
- Escape and F (scoped to Player page)

Missing: arrow-key navigation within grids, Space for play/pause forwarding to the iframe, Enter to select focused card. These aren't trivial — grid focus management requires tracking a focus index and scrolling to the focused card — but they're listed as P0 requirements.

## Dead stores

`contentStore.js` defines a Zustand store with `movies`, `tvShows`, `currentMovie`, `currentTVShow`, `searchResults`, etc. No component imports or uses it. All data fetching is handled by React Query hooks (`useQuery`, `useInfiniteQuery`) in each page component.

Similarly, `playerStore.js` is imported nowhere in the component tree. The `VideoPlayer` component calls `saveWatchProgress` from `player.js` directly, and the `Home` page calls `getAllWatchProgress` from `player.js` directly. The Zustand player store's in-memory `watchProgress` map is never populated during normal playback and never read during rendering.
