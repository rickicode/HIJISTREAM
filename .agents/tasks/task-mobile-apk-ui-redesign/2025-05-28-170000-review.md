# Mobile APK UI redesign: My List tab, hero rework, IMDB badges, clickable genres

A broad UI refresh across the mobile Expo app and the React web app. The Downloads tab is replaced by a My List (Favorites) placeholder. The Home hero banner is made taller and less obscured by gradient overlays. Every content rail gains a "View All" button. The genre detail page gets a colored hero header and pill-style sort filters. Genre tags on detail pages become navigable. The "More Like This" section switches from a horizontal scroll to a 3-column vertical grid. IMDB rating badges appear on content cards across both platforms. All hardcoded English strings are moved to i18n keys, and 14 locale files are updated consistently.

Watch for: Genre navigation relies on a hardcoded English-to-ID mapping that will silently fail for any locale whose genre names don't match the lookup table (confirmed). The "View All" on Continue Watching routes nowhere (confirmed noop handler). The vertical recommendation grid uses a magic-number width formula that breaks on narrow or extra-wide screens (likely).

## High-level view

Genre navigation is the riskiest piece. `DetailHero` converts genre pill text into TMDB genre IDs via a hardcoded English mapping (action -> 28, comedy -> 35, etc.). Since genre text comes from the API in the user's locale, this lookup silently fails for any non-English language, making genre pills non-functional for ~6 of the 7 supported locales.

The recommendation grid in movie and TV detail pages computes card width as `(screenWidth - 52) / 3`. This works for typical phone widths but has no responsiveness for tablets, landscape, or split-screen.

The hero banner redesign trades vertical content density for immersion: 55% screen height, softer gradients, a rating badge in the corner. Both the hero's "My List" button and the Continue Watching "View All" are noop handlers, rendering interactive elements that do nothing when tapped.

i18n key migration is thorough across all 14 locale files with consistent key structures.

<summary>Issues (5)</summary>

1. **Genre pill navigation broken for non-English locales** — `findGenreId()` in DetailHero normalizes genre text and compares against English keys. When the app runs in Japanese, Korean, Indonesian, etc., the genre names returned by TMDB won't match. Add a reverse lookup by TMDB numeric ID (genres are returned with IDs in the detail response) or store the genre ID alongside the name.
2. **Continue Watching "View All" is a noop** — The `onSeeAll` callback is `() => {}`. Either implement the navigation target or remove the button for this rail to avoid dead-end UX.
3. **Recommendation grid width formula fragile** — `(screenWidth - 52) / 3` assumes 16px padding on each side plus 10px gaps for 2 gutters (16+16+10+10=52). If padding or gap values change, cards overflow or leave visible whitespace. Extract the arithmetic from the constants used in the stylesheet.
4. **Web rating badge shows twice per card** — The web `ContentCard` renders a rating badge in the absolute-positioned overlay AND a separate `<span>` with the rating below the title. Consider removing the inline text rating when the badge is present to reduce visual noise.
5. **HeroBanner "My List" button is a noop** — The `+` button in the hero calls `() => {}`. Non-functional interactive elements reduce trust.

## Genre pill navigation via English-only mapping

`DetailHero.jsx` introduces `findGenreId(genreName)` which lowercases and strips spaces from genre text, then looks it up in a hardcoded object:

```javascript
const mapping = {
  action: 28, adventure: 12, animation: 16, comedy: 35, ...
};
return mapping[normalized] || null;
```

The `item.genre` field comes from the TMDB API response and is locale-dependent. A user running the app in Japanese sees `genreName = "アクション"` which normalizes to `"アクション"` and produces `null`. The pill renders but `handleGenrePress` quietly does nothing because `if (genreId)` fails.

The fix is structural: TMDB detail responses include `genres` as an array of `{id, name}` objects. If the backend normalizes these into a comma-separated string, it should also surface the IDs (e.g., as a parallel `genre_ids` field). The component can then navigate by ID directly without text matching.

## Recommendation grid layout assumptions

Both `movie/[id].jsx` and `tv/[id].jsx` render recommendations identically:

```javascript
<View key={...} style={{ width: (screenWidth - 52) / 3 }}>
  <ContentCard item={item} type="movie" />
</View>
```

The `52` derives from `spacing.md` (16) on each side plus two 10px gaps. But the gap is set via `gap: 10` on the parent `recommendGrid` style and the padding via `padding: spacing.md` on `recommendSection`. If either value is changed independently, the formula silently becomes wrong.

On tablets or landscape orientation, 3 columns at this width produces cards that are disproportionately large. No column-count adjustment exists for wider viewports.

## Noop interactive elements

Two interactive elements render with no backing logic:

- `HeroBanner`: The "My List" (`+`) button passes `onPress={() => {}}`. Users will tap it expecting to save a title.
- `home.jsx`: Continue Watching rail's `onSeeAll={() => {}}` renders a "View All >" link that navigates nowhere.

Both fail silently. The other four rails all navigate to `/(tabs)/browse` which is a generic landing rather than a context-specific list, but at least functional.

## Web content card dual rating display

The web `ContentCard` shows the rating badge (top-right overlay) and also renders the rating inline below the title:

```jsx
{item.rating && item.rating !== '0.0' && (
  <span className="text-xs text-muted-foreground">
    <span className="text-yellow-400">&#9733;</span> {item.rating}
  </span>
)}
```

Both render the same data in close proximity. Mobile shows only the badge. The web duplicates visual information on cards that are 150-180px wide.
