# Mobile APK UI redesign with locale-aware genre navigation and responsive grid (v2)

The five issues from the first review pass have all been addressed. Genre navigation now uses an i18n reverse lookup instead of a hardcoded English mapping, resolving the multi-locale failure. Continue Watching no longer renders a dead "View All" button. The recommendation grid computes card width from spacing constants and adapts column count to screen width. The web ContentCard removed the duplicate inline rating text. The HeroBanner "My List" noop was accepted as intentional (feature placeholder).

Watch for: Genre pills on TV show detail pages still fail silently for TV-specific genre IDs (10759, 10765, etc.) that aren't in `GENRE_IDS` (confirmed). The i18n reverse lookup depends on locale translations exactly matching TMDB's genre names for that language (likely fragile for edge cases). The `SearchModal` debounce saves to history on every keystroke pause, not on explicit submission (confirmed, minor UX noise).

**Verdict**: APPROVED

## High-level view

The genre navigation fix is well-designed. `DetailHero` builds a reverse map from translated genre names to numeric IDs at render time, falling back to an English-only normalized lookup for edge cases. This handles the 7 supported locales correctly as long as the i18n `genres.*` values match TMDB's API translations for that language. TV-specific genres (Action & Adventure, Sci-Fi & Fantasy, etc.) remain unmapped because `GENRE_IDS` only covers movie genres, making those pills inert on TV detail pages.

The grid fix replaces the magic `52` with a formula derived from `spacing.sm` and `spacing.md` constants, and selects 3, 4, or 5 columns based on screen width breakpoints. This handles phone, tablet, and landscape correctly.

The web search modal is a well-scoped addition: Ctrl+K shortcut, debounced live results, search history persistence, Escape/click-outside dismissal. It integrates cleanly into the existing Layout component.

The backend's English fallback for missing translations (movie and TV detail endpoints) is implemented identically across all three routing files, with a second TMDB fetch only when `overview` is empty and the requested language isn't already English.

## TV genre ID gap in clickable pills

The `GENRE_IDS` map in `apps/mobile/src/utils/api.js` contains only movie-specific TMDB genres:

```javascript
export const GENRE_IDS = {
  action: 28, adventure: 12, animation: 16, comedy: 35, crime: 80,
  documentary: 99, drama: 18, family: 10751, fantasy: 14, history: 36,
  horror: 27, music: 10402, mystery: 9648, romance: 10749,
  scienceFiction: 878, tvMovie: 10770, thriller: 53, war: 10752, western: 37,
};
```

The middleware's `GENRE_MAP` (used for list item display) includes TV genres like 10759 (Action & Adventure) and 10765 (Sci-Fi & Fantasy), but the client-side `GENRE_IDS` does not. When a TV show's detail response includes genres like "Sci-Fi & Fantasy", `findGenreId()` tries the translated reverse lookup, fails, then tries the English fallback, and returns `null`. The `handleGenrePress` silently aborts:

```javascript
const handleGenrePress = (genreName) => {
  const genreId = findGenreId(genreName);
  if (genreId) {  // null → does nothing
    router.push(`/genre/${genreId}`);
  }
};
```

The pill still renders as a `TVFocusable` with pressable styling, which misleads the user. Either extend `GENRE_IDS` with TV genres and add i18n keys, or render genre pills as non-pressable `View` when `findGenreId` returns null.

## SearchModal history accumulation

The debounce callback in `SearchModal` saves to history unconditionally when the debounced value is non-empty:

```javascript
debounceRef.current = setTimeout(() => {
  setDebouncedQuery(value.trim());
  if (value.trim()) {
    const updated = [value.trim(), ...getSearchHistory().filter((q) => q !== value.trim())].slice(0, 10);
    setHistory(updated);
    saveSearchHistory(updated);
  }
}, 300);
```

If a user types "avatar" with a 400ms pause after "ava", history will contain both "ava" and "avatar". The history array is capped at 10, but intermediate entries push out legitimate past searches. The fix is to move `saveSearchHistory` into `handleKeyDown` (the Enter handler) and `handleResultClick`, and only use the debounce for triggering the API query.
