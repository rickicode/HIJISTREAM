# Audit fixes: cache alignment, input validation, ID regex, and TMDB 404 handling (v2)

This change addresses a code audit plus a user-reported 404 bug when clicking movies/series after an APK update. The fixes align client-side cache TTLs with PRD (24h/7d/30d/1h), add input validation for `page` and `query` across all three deployment targets, limit ID regex to 20 characters, improve cache eviction to O(k), stabilize the hero selection, harden the VideoPlayer origin allowlist, and propagate TMDB 404s as proper 404 responses with user-friendly messages.

**Watch for:** No blocking concerns remain. The server/client TTL divergence (5min server vs 24h client) is an intentional tiered caching architecture. The 24-hour localStorage cache is a PRD requirement.

**Verdict**: APPROVED

## High-level view

The v1 review raised five issues. Three were fixed: input validation was added to `middleware.js` and `functions/api/[[path]].js` (page 1-1000, query non-empty ≤200 chars), the ID regex was tightened from unbounded `[\w]+` to `[\w]{1,20}` across all three handlers, and cache eviction was replaced with an O(k) Map-iteration approach that deletes the first 10% of entries by insertion order. Two were intentionally kept: server/client TTL divergence (valid tiered proxy vs per-device caching) and the 24-hour localStorage cache (explicit PRD specification).

The validation logic is now consistent across all deployment paths. Each `fetchTMDB` propagates `err.status`, and all three catch blocks distinguish 404 from other errors.

## Verification summary

**Input validation parity** — Confirmed identical page (1-1000) and search query (non-empty, ≤200 chars) validation in `apps/server/src/index.js`, `apps/web/middleware.js`, and `apps/web/functions/api/[[path]].js`. All return 400 with descriptive error messages.

**ID regex length-bound** — All ID-matching regexes now use `([\w]{1,20})` across the Bun server, Vercel middleware, and Cloudflare Pages function. The 20-char cap prevents memory-bloating cache keys while accommodating any plausible TMDB ID format.

**Cache eviction O(k)** — The server's `setCache` iterates the Map key iterator for `Math.floor(MAX_CACHE_SIZE * 0.1)` entries, deleting from the front. O(k) where k=1000, triggered only at capacity, no repeated triggering until 1000 new entries fill back up.

**Intentional TTL divergence** — Server TTLs (5min/10min/2min) act as a shared proxy cache for concurrent users. Client TTLs (24h/7d/30d/1h) are per-device caches per PRD spec. This tiered architecture is valid.
