# TMDB catalog proxy replacing VidAPI for all content data

The entire data pipeline has been rerouted: catalog data (listings, details, search, seasons/episodes) now comes from TMDB via a server-side proxy layer, while VidAPI (vaplayer.ru) is retained exclusively for video embed URLs. The proxy exists in three identical forms — Bun backend server, Vercel Edge Function, and Cloudflare Pages Function — each performing the same TMDB fetch, response transformation, and caching. The frontend API client is now a thin wrapper that hits `/api/*` relative paths, never touching TMDB directly.

Watch for: **(1)** DetailHero renders cast members as `[object Object]` because it treats `item.credits` entries (objects with `name`, `character`, `profile_path`) as plain strings — **confirmed**. **(2)** Render.com deployment is broken: `render.yaml` declares a `static` site with a `TMDB_API_KEY` env var but no server runtime to use it, and the old VidAPI rewrite was removed without replacement — **confirmed**. **(3)** ~450 lines of TMDB proxy logic are copy-pasted across three files with no shared module; any future bug fix must be applied three times — **confirmed**.

## High-level view

The proxy layer is the core of this migration: three independent deployments (Bun server, Vercel Edge, Cloudflare Function) each embed the same ~150-line transform module and route table. TMDB responses are normalized into a consistent shape (`{ id, title, year, poster_url, embed_url, ... }`) that the frontend consumes without knowing the upstream source. The design keeps the TMDB key server-side and fronts all access through `/api/*`, which is the right boundary.

The frontend refactor is straightforward: the old page-offset simulation of VidAPI's single `/movies/latest/page-N.json` endpoint is replaced by category-specific calls (popular, trending, top-rated, upcoming). New detail and season endpoints enable real movie overviews, cast lists, and per-episode navigation. The mobile API client mirrors the web client identically, pointing at the Vercel deployment by default.

The Render.com deployment cannot serve API requests. The `render.yaml` still declares `runtime: static`, the VidAPI rewrite is gone, and there is no alternative way for the static frontend to reach TMDB. Users deploying via Render will get a broken site — frontend loads, API calls 404.

The transform unit tests validate the normalization logic offline (no network), which is a solid pattern. The integration tests hit the live Vercel deployment and gracefully skip when unavailable — reasonable for CI, but means the test suite can pass without exercising any real code path if the deployment is down.

## DetailHero cast rendering bug

The backend transform produces:
```json
"credits": [{ "name": "Brad Pitt", "character": "Tyler Durden", "profile_path": "/path.jpg" }, ...]
```

DetailHero does:
```jsx
const cast = item.credits?.slice(0, 5) || [];
// ...
{cast.map((actor) => (
  <span key={actor}>{actor}</span>
))}
```

`actor` is an object, not a string. React will render it as `[object Object]` and the `key` will also be `[object Object]` for every entry, causing both a visual bug and a React key collision warning. The fix is `key={actor.name}` and rendering `{actor.name}`.

## Render.com deployment gap

The previous `render.yaml` had:
```yaml
routes:
  - type: rewrite
    source: /api/*
    destination: https://vidapi.ru/*
```

This was removed and replaced with only:
```yaml
envVars:
  - key: TMDB_API_KEY
    sync: false
```

But the service type remains `static`. Render static sites cannot run edge functions or access env vars at runtime. The TMDB_API_KEY is useless here. The frontend will make requests to `/api/movies/popular` which will be caught by the SPA `/* -> /index.html` rewrite and return HTML.

## Proxy code triplication

The three proxy files (`apps/server/src/index.js`, `apps/web/api/[...path].js`, `apps/web/functions/api/[[path]].js`) each contain:
- Identical `GENRE_MAP` (26 entries)
- Identical `mapGenreIds`, `transformMovieListItem`, `transformTVListItem`, `transformMovieDetail`, `transformTVDetail`, `transformSeason`, `transformSearchResults`, `wrapPaginatedList` functions
- Identical route matching logic

The Cloudflare and Vercel functions have constraints (no local imports in edge functions for Cloudflare, single-file requirement for Vercel), which partially explains the duplication. But the Bun server has no such constraint and could import from a shared package. At minimum, a build step that inlines a shared source file would prevent drift between the three implementations.

## Movie embed URL uses different ID types depending on context

In list transforms:
```js
embed_url: `https://vaplayer.ru/embed/movie/${movie.id}`,  // TMDB numeric ID
```

In detail transform:
```js
embed_url: `https://vaplayer.ru/embed/movie/${movie.external_ids?.imdb_id || movie.imdb_id || movie.id}`,  // IMDB string ID preferred
```

And `MovieDetail.jsx` also does:
```js
const playId = movie.imdb_id || movie.id || id;
navigate(`/player/movie/${playId}`);
```

So a user browsing a list sees an embed URL like `/embed/movie/550`, but viewing the detail page produces `/embed/movie/tt0137523`. If vaplayer supports both, this works but defeats caching (two different cache entries for the same content). If it only supports one format, one of these paths produces broken embeds.

## Test coverage shape

The transform unit tests (`transform.test.js`) are well-structured: they cover genre mapping edge cases, null/missing fields, and embed URL format — all without network. This is the right pattern for a proxy transform layer.

The integration tests hit the live Vercel deployment at `https://hijistream-web.vercel.app/api`. Every test guards with `if (!data) return;`, which means network failures or API key misconfiguration results in a green test suite with all tests skipped. There's no mechanism to detect "the API is just broken" vs "the API returned valid data". The single test that doesn't skip — pagination comparison — still has this guard on both fetches.

Not tested: the Bun server's in-memory cache eviction (FIFO when hitting 10,000 entries), the Cloudflare Function variant, error propagation when TMDB returns non-JSON, or the `setInterval` cache cleanup (which also prevents the Bun process from ever exiting cleanly without `unref()`).

## Server cache cleanup interval prevents clean exit

```js
setInterval(() => {
  // cleanup expired entries
}, 5 * 60 * 1000);
```

This interval keeps the Bun process alive indefinitely, which is fine for a long-running server but prevents graceful shutdown in test or container environments. Calling `.unref()` on the interval or clearing it on SIGTERM would be cleaner. Not a production issue for the intended use case, but worth noting for testability.
